# Batch V0.4 / человеческое ожидание

Выбор пользователя: подход Bandits Slayer — IsoZombie как сетевая оболочка,
собственные человеческие анимации и собственная логика BAO.

## Сделано

- Уникальные ID и runtime-привязки всех тестовых NPC; нет ограничения одного живого.
- Horde Manager передаёт количество и радиус; повторный спавн на одной клетке разрешён.
- До 20 за запрос и 50 активных объектов; это ограничение экспериментального спавнера.
- Частичный результат сообщает spawned; смерть и очистка независимы для каждой записи.
- REMOVE ALL удаляет всех тестовых NPC BAO; объекты с неуспешной очисткой остаются в учёте.
- Серверный список синхронизируется с картой клиентов; обычные зомби не получают BAOHuman.
- Первый собственный AnimSet использует игровой Bob_Idle только при BAOHuman=true.

## Тест в игре

1. Перезапустить сервер и все клиенты с одной версией мода.
2. Включить admin, открыть Horde Manager, выбрать открытую клетку рядом на своём этаже.
3. Выбрать BAO: создать NPC; количество 5, радиус интерфейса 1, height offset 0.
4. На той же клетке создать ещё 3. Ожидается 8 объектов с отдельным учётом.
5. Убить одного, создать ещё одного — ручная очистка перед спавном не нужна.
6. Оценить стойку ожидания и убедиться, что обычные зомби рядом не изменились.
7. Выбрать BAO: удалить всех тестовых NPC и нажать Spawn.
8. Проверить исчезновение живых тестовых NPC на клиентах. Трупы намеренно сохраняются.

F10 создаёт одного рядом, REMOVE ALL TEST NPC удаляет всю тестовую группу.
Сервер пишет Batch spawned=N requested=N active=N; клиент получает spawned=N.
request_sent означает отправку, а не успешное создание. При частичном результате
смотреть reason и spawned. Лимит radius внутренний 0–10, в vanilla UI это 1–11.

## Что ещё не готово

Новый AnimSet не отрисовывался в этой сессии PZ: XML/код проверяются офлайн, окончательное
подтверждение выбора idle — визуальное. Ходьба, бег, бой и реакции не считаются готовыми.
Полная внешность человека тоже не реализована. Запись анимаций пока не нужна.

Спавнер не принимает решений за NPC. Decision → Action → Executor → Navigation остаётся
архитектурой поведения; пока эти модули singleton, групповой самостоятельный AI не заявляется.
Нужен следующий этап с независимым состоянием на NPC и фактическим игровым patrol.
NPC пока не имеют полноценного сохранения/восстановления между рестартами.
