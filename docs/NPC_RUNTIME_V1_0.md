# NPC Runtime V1.0

## Продолжение: World Adapter V0.2

В F10 добавлены SPAWN TEST NPC и REMOVE TEST NPC. Окно увеличено до 430 пикселей.
После полного перезапуска игры в одиночном тестовом мире:

1. Встать на свободном участке и нажать SPAWN TEST NPC.
2. Проверить появление персонажа рядом; записать, виден ли он и как выглядит.
3. Нажать SPAWN TEST NPC повторно: ожидается REFUSED / test_npc_exists.
4. Нажать REMOVE TEST NPC: ожидается OK / removed и исчезновение персонажа.
5. Повторить создание и удаление один раз, затем проверить console.txt.

Логи: `[BAO][NPCWorldAdapter] Test NPC spawned ...` и `Test NPC removed`.
`spawned` означает возврат объекта фабрикой и привязку к NPCData, но ещё не подтверждает
видимость и физическое движение. При cleanup_pending повторить REMOVE TEST NPC.
В MP ожидается singleplayer_only. Автоматического спавна и patrol пока нет.
Офлайн проверены повторное создание, отказ занятой клетки, MP, отсутствие результата
фабрики, запрет удаления при активном пути и восстановление после ошибки очистки.

Ниже — описание первоначального этапа V0.1.

Этап добавляет безопасную связь между постоянной записью NPC и временным объектом
персонажа в загруженном мире. Самостоятельный спавн пока намеренно отключён: сначала
игра должна подтвердить Lua-доступ к API Build 42.21.0.

## Добавлено

- `42/media/lua/shared/npc/BAO_NPCRuntime.lua` — реестр `npcId → character`.
- `42/media/lua/shared/npc/BAO_NPCWorldAdapter.lua` — одноразовая проверка API при
  `OnGameStart`, без создания объектов.
- `42/media/lua/shared/tests/BAO_NPCRuntimeTestHarness.lua` — изолированный набор
  тестов на синтетических персонажах.
- `BAO_NPCData.Remove()` теперь освобождает существующую runtime-привязку до удаления
  постоянной записи.

Реестр не подписан на `OnTick`, не сканирует список объектов мира и не запрашивает путь.
Координаты читаются при `Bind()` и только при явном `Refresh()`. Один объект персонажа
не может быть привязан сразу к двум NPC; игрок отклоняется.

## Проверка в игре

1. Полностью перезапустить Project Zomboid и открыть тестовый мир.
2. Не требуется нажимать кнопку и не требуется создавать NPC.
3. Закрыть игру или сообщить, что загрузка завершена; затем проверить свежий
   `C:\Users\Vovan\Zomboid\console.txt`.

Ожидаемые строки:

```text
[BAO][NPCRuntimeTestHarness] NPC RUNTIME V1.0 TOTAL=17 PASS=17 FAIL=0
[BAO][NPCRuntimeTestHarness] STATUS: ALL TESTS PASSED
[BAO][NPCWorldAdapter] API probe ready=true ... instantiate=true ... getCell=true
```

Если `ready=false`, подробные флаги в той же строке покажут отсутствующую часть API.
Это диагностический результат, а не ошибка игры.

## Следующий этап

После `ready=true` адаптер получает явные операции создания и удаления одного тестового
`IsoSurvivor`. Созданный объект будет помечаться `ownedByBAO`, привязываться через
`NPCRuntime` и только затем передаваться в существующий путь
Decision → Action → Executor → Navigation. Автоматического появления NPC при загрузке
мира не будет.
