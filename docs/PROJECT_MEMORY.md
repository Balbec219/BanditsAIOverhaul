## Цель и ограничения

Самостоятельная NPC/AI-система Project Zomboid Build 42.20+.
Главная идея: люди принимают решения и оставляют последствия, а не просто следуют за игроком.
WORLD → NPC → DECISION → ACTION → RESULT → CONSEQUENCE → WORLD.
Личность и опыт могут конфликтовать с доктриной фракции.
Долгосрочно: память, отношения, потребности, цели, отряды, фракции, поселения,
радиосвязь с оценкой достоверности, транспорт и саботаж, события без игрока,
Creator/Admin UI, sandbox settings, RU по умолчанию / EN по выбору.
Масштабирование: full/reduced/abstract simulation, интервалы и событийные обновления.
Совместимость с vehicle upgrade mods важна. Workshop IDs из ТЗ — только непроверенные references.
AdvancedAnimator / missing AnimSets/actiongroups отложены.
Не смешивать client UI и server logic. Не использовать B41 API без проверки B42.
Сначала изучить существующий модуль, затем расширять. Не плодить harness.

### Конкретные разрывы

1. AIController создаёт Action длительностью 3600, но не создаёт Execution.
   Поиск не обнаружил runtime-вызова ActionSystem.Update в Lua-дереве.
2. Executor хранит actionId и план, но ExecuteStep не выполняет действие,
   не запускает Navigation и не синхронизирует результат с ActionSystem.
3. Controller, Executor и Navigation имеют общее одиночное состояние;
   это ещё не независимые контроллеры для нескольких NPC.
4. Ручной AITestHarness не сравнивает решение с ожидаемым; DebugUI выводит PASS
   при любом непустом результате. Историческое 9/9 не заменяет новую проверку поведения.
   Сценарии двух harness различаются (например Ranged, Health, Pain), нельзя механически
   перенести Expected без проверки профиля и контекстов.
5. При смене решения Controller записывает новое currentDecision до фиксации результата
   старого action; история может получить неверный Decision. Отказ interrupt не мешает
   попытке запуска нового action. После завершения прежнее решение не создаёт новый action.
6. Navigation определяет прибытие по XY без проверки Z; нет контроля зависшего пути.
   Cancel меняет учётное состояние, но не посылает character команду остановки.
7. Bridge emergency читает health/panic/zombiesNearby с маленькой буквы,
   тогда как AI-сценарии используют Health/Panic/ZombiesNearby.
8. Существующие Action/Executor/Controller harness очищают или изменяют общее состояние;
   перед интеграционными тестами нужна изоляция и восстановление runtime.

## Следующая интеграционная задача

Связать AIController ↔ ActionExecutor ↔ ActionSystem для одного действия.
Изменять существующие файлы, начиная с них и соответствующих harness.

Критерии готовности:
- одно решение создаёт один Action и один Execution;
- повторные Update не создают дубликатов;
- завершение/ошибка Execution отражаются в Action и истории Controller ровно один раз;
- смена решения корректно прерывает старую пару; отказ interrupt не теряет старое действие;
- история хранит decisionId именно завершённого действия;
- тесты не оставляют изменений в текущем AI игрока;
- контракт повторного действия после завершения определён явно.

Затем подключить существующую Navigation к одному patrol с явно заданными character
и destination. Успех — только после реального прибытия, с проверкой этажа, отказа,
отмены и таймаута. Сначала изолированные проверки, потом интеграция, затем реальный NPC.
Не выдавать таймер или вручную завершённый execution за реально выполненный patrol.
