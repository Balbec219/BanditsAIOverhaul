# План аудита производительности BAO

Пожелание пользователя: минимизировать нагрузку при разработке и отдельно проверить
модули на возможность оптимизации. Без полного переписывания и без недоказанных обещаний FPS.

## Уже сделано

Navigation V1.3: опрос активного пути раз в 0.1 с, ранний выход в простое, одно чтение XYZ,
один запрос пути на действие, подробная диагностика по запросу, ограниченная история.
Офлайн проверены счётчики запросов и опросов. Измерений FPS/CPU в игре ещё нет.

## Что измерять после первого настоящего NPC

1. Записать базовую сцену/мир, набор модов и условия; сравнивать одинаковые условия.
2. Снять время кадра и число активных NPC при 1, затем нескольких NPC.
3. Для модулей измерить частоту вызовов, время работы, размеры временных таблиц/истории
   и объём логов. Накладные расходы самого профилирования также учитывать.
4. Сначала исправлять измеренные дорогие участки. После каждого изменения проверять
   скорость реакции на угрозу, остановку маршрута и корректность решений.

## Кандидаты для исследования по текущему коду

| Модуль | Что проверить, не утверждая заранее, что это узкое место |
| --- | --- |
| WorldContext | Перебор getZombieList и расчёт близости; реальные интервалы, объём списка, повторные чтения |
| DecisionSystem | Частота пересчёта scores, создание таблиц, условия изменения контекста |
| AIController / ActionExecutor | Работа OnTick при неизменном решении/состоянии; возможность событий или разных интервалов |
| Navigation | Частота polls, запросы пути, время до stuck/arrival; баланс задержки реакции и нагрузки |
| NavigationMovementTest и остальные harness | Отключение завершённых диагностик, отсутствие фоновой работы и лишних логов |
| ActionSystem / истории | Рост реестра завершённых действий, владение ссылками, ограничение памяти без потери результатов |

## Позже, при нескольких NPC

Раздельное состояние NPC, распределение обновлений по времени, дистанционные уровни
симуляции, события вместо пересчёта без изменений. Не добавлять преждевременно сложный
планировщик: сначала подтвердить потребность измерениями и жизненным циклом NPC.
